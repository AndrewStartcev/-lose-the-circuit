## Критичное правило по визуалу

Изображения, приложенные пользователем как примеры экранов/ассетов, являются **art-direction visualizations**, а не точной спецификацией игры.

Они НЕ определяют автоматически:

- состав механик;
- экономику и монеты;
- расположение HUD;
- точные размеры элементов;
- состав экранов;
- готовые production assets.

Источник истины для механики — `docs/GDD.md` и `docs/TECHNICAL_PLAN.md`. Источник истины для production-графики — реальный graybox + `docs/ASSET_MANIFEST.md`.

## Scope

- Не переписывать уже работающие системы без причины.
- Не менять утверждённую механику/баланс/visual style вне scope задачи.
- Не добавлять прямые Yandex/Pikabu SDK calls в gameplay.
- Не создавать финальный asset pack без реальных UI slots.
- Не считать Editor run достаточным тестом Web build.
- Production UI собирать из отдельных элементов, а не одним скриншотом/PNG.
- Изменяемые тексты, числа, цены, уровень, счёт и награды не запекать в графику.

## Геометрия проводов — обязательный контракт

Все проводники строятся из одной общей геометрической системы:

- квадратный logical tile;
- точки подключения строго по центру четырёх сторон;
- одинаковый диаметр всех портов;
- нулевая перспектива внутри gameplay tile;
- поворот на `90°` обязан давать пиксельно/геометрически совместимое соединение;
- straight/corner/T/cross нельзя рисовать как независимые произвольные иллюстрации;
- состояние `energized` не меняет форму и положение трубы — только материал/свет/FX.
